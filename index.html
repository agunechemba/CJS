Welcome

Hello, Future Programmer

Every wizard starts as an apprentice.

Somewhere near you is a machine that can count faster than you can blink, remember more words than you will ever read, and follow instructions with perfect patience. That machine is a computer. But it is also a very silly machine. It can do almost nothing on its own. It needs you to tell it exactly what to do — one tiny step at a time.

Those tiny steps are called code. And the person who writes them is called a programmer. That, very soon, will be you.

This book is a journey in three parts:

  • Part One — Adventurers. You will meet JavaScript, set up your tools, and learn about values, variables, and arrays. Perfect for ages five to eight.
  • Part Two — Explorers. You will make decisions, loop around, build functions, craft objects, and bring web pages to life with the DOM, events, forms, and graphics. Great for ages nine to eleven.
  • Part Three — Masters. You will crack secret codes with regular expressions, tame time with callbacks and closures, speak to the internet with AJAX and JSON, and control the whole browser. For ages twelve and thirteen.

You do not need a fancy setup to follow along. Any browser, a code editor, and a curious mind will do. The examples in this book are little seeds. Plant them, water them, break them, fix them, and grow them into something of your own.

Ready? Let us begin.

Before You Go

  • A program is a set of instructions for a computer.
  • JavaScript is the language that lives inside every web browser.
  • You do not have to be a genius. You have to be patient and curious.
  • Every programmer, every day, writes mistakes. That is how we learn.

Warm-Up Questions

  1. What is one website you love? What does it do when you click things?
  2. Can you think of three machines in your home that run some kind of code?
  3. What does the word "instruction" mean to you?

Part One · Adventurers · Chapter One

The World's Most Misunderstood Language

What JavaScript is, where it came from, and why it matters.

Long ago — well, in 1995, which is long ago for a computer — web pages were flat and still. They were like posters on a wall. You could look at them, but you could not talk back. Then a programmer named Brendan Eich was given a wild challenge: invent a language for the browser, and do it fast. He did. Legend says it took him only about ten days. The language was first called Mocha, then LiveScript, and finally — mostly as a marketing trick, because Java was the cool new thing — it was renamed JavaScript.

JavaScript is not the same as Java. They are like a cat and a caterpillar: they share a few letters, and that is all. JavaScript is its own creature. It is a dynamic scripting language, which means the browser reads your code and runs it right away, line by line, without a separate compiling step.

JavaScript lives almost everywhere. It lives inside your web browser, where it makes pages interactive — buttons that respond, menus that drop down, forms that check themselves. It lives inside phones and tablets, inside server programs, even inside robots and smart fridges. But its first home, and still its most important home, is the web browser.

Here is what JavaScript is not. It is not a toy. It is not dead. It is not the same as Java. And it is not buggy and different in every browser — that was true long ago, and the browsers have agreed on the standards now.

Key Ideas

  • JavaScript was created in 1995 by Brendan Eich at Netscape.
  • Its original names were Mocha and LiveScript.
  • It is an interpreted language — no separate compile step.
  • Its home is the browser, but it runs anywhere a JavaScript engine exists.
  • JavaScript is not Java. Different language, different purpose.

Try It Yourself

  1. Open a web page in your browser and press F12. Find the tab that says "Console." That is where JavaScript lives.
  2. Name three things on a web page that would not work without JavaScript.
  3. Ask a grown-up: what was the web like before smartphones?

Part One · Adventurers · Chapter Two

Writing Your First JavaScript Program

Tools, consoles, and a very small hello.

Before you can tell a computer what to do, you need two things: a browser and a code editor. The browser runs your code; the editor is where you write it. Chrome is a wonderful browser for this, and the editor we like is called Sublime Text — but any editor will do.

Once you have both, you can run JavaScript in three different ways. The first is to put it directly on an HTML element, like this:

<button onclick="alert('Hello, world!');">Click Me</button>

The second way is to put your code inside a <script> element. The third way — and the tidiest — is to put your code in a separate .js file and link to it:

<script src="myScript.js"></script>

But the fastest way to test a quick idea is the JavaScript Console. In Chrome, open it with Ctrl + Shift + J on Windows or Cmd + Option + J on a Mac. The console is like a friendly scratchpad. Type something, press Enter, and the computer answers immediately.

console.log("Hello, world!");
// → Hello, world!

You can also leave comments in your code. The computer ignores them, but people love them. Use // for a single-line note, and /* ... */ for a longer block.

// this is a single-line comment
/*
   this is a
   multi-line comment
*/

Two small warnings. JavaScript is case-sensitive — plants and Plants are not the same word. And it does not care about white space, so indent your code to keep it tidy. You will thank yourself later.

Key Ideas

  • You need a browser and a code editor to write JavaScript.
  • You can include JavaScript in an HTML attribute, in a <script> element, or in an external .js file.
  • The JavaScript Console is the fastest way to try something small.
  • Comments start with // or are wrapped in /* ... */.
  • JavaScript is case-sensitive. plants ≠ Plants.

Try It Yourself

  1. Open the JavaScript Console and print your name with console.log.
  2. Write a short comment above the code explaining what it does.
  3. Try alert("Hello!") in the console. What happens?

Part One · Adventurers · Chapter Three

Name Tags for Values

Variables, data types, and how to keep things tidy.

Imagine a magic cupboard with a hundred little doors. On every door, you stick a name tag: myAge, favoriteColor, cookieCount. Behind each door sits a value — a number, a word, a yes-or-no. The name tag is how you find the value again. Programmers call this a variable.

In JavaScript, you can create a variable in three ways. The oldest is var:

var myAge = 10;
console.log(myAge); // → 10

The modern way is let, which creates a variable you can change later:

let myAge = 10;
myAge = 11;
console.log(myAge); // → 11

And when a value should never change, use const:

const birthday = "May 3rd";
// birthday = "June 1st"; // ERROR!

JavaScript values come in a few basic kinds, called data types. A number is for counting. A string is for text, wrapped in quotes. A boolean is either true or false. There is also a special value called NaN ("Not a Number"), which appears when math goes wrong, and undefined, which is what a variable holds before you give it a value.

let score = 42;          // number
let name = "Ada";        // string
let ready = true;        // boolean
let mystery;             // undefined
console.log("eggs" * 2); // → NaN

One important rule: always use var, let, or const when you create a variable. If you forget, JavaScript will create a global variable without asking — and that can cause strange bugs later. Always declare your variables on purpose.

Key Ideas

  • var, let, and const create variables.
  • Use let for values that change; use const for values that don't.
  • Basic data types: number, string, boolean, NaN, undefined.
  • Always declare a variable on purpose — never let one slip into global scope by accident.
  • Name variables clearly. myAge beats x.

Try It Yourself

  1. Create a const called myName and print it.
  2. Create a let called myScore, then change it twice.
  3. Print the result of "5" + 1 and 5 + 1. Are they the same? Why not?

Part One · Adventurers · Chapter Four

Lists of Things

When one value is not enough.

Suppose you want to remember a whole shopping list — milk, eggs, bread, apples. You could make four separate variables, but that gets messy fast. Programmers have a better tool: the array.

An array is an ordered list of values, written with square brackets and separated by commas:

let shopping = ["milk", "eggs", "bread", "apples"];

console.log(shopping[0]);     // → milk
console.log(shopping[2]);     // → bread
console.log(shopping.length); // → 4

Notice three things. First, the items go inside square brackets. Second, you pull an item out by putting its position in brackets after the name. Third — and this one surprises everyone — the first item is at position zero, not one. Programmers count from zero.

You can also create an empty array and add things later, or even build an array that contains other arrays. Those are called multidimensional arrays.

let bestAlbumsByGenre = [];

bestAlbumsByGenre[0] = "Country";
bestAlbumsByGenre[0][0] = "Johnny Cash: Live at Folsom Prison";
bestAlbumsByGenre[0][1] = "Patsy Cline: Sentimentally Yours";

bestAlbumsByGenre[1] = "Rock";
bestAlbumsByGenre[1][0] = "Nirvana: Nevermind";

Arrays have superpowers. You can push onto the end, pop off the end, and loop over every item. There are dozens of array methods — concat, indexOf, join, reverse, sort, and more — each one a tiny tool in your toolbox.

let animals = ["tiger", "bear"];
animals.push("otter");
console.log(animals); // → ["tiger", "bear", "otter"]

for (let animal of animals) {
  console.log("I see a " + animal);
}

Key Ideas

  • Arrays hold ordered lists of values.
  • Indexes start at 0. The last index is length - 1.
  • You can store any type of data in an array, even other arrays.
  • push adds to the end; pop removes from the end.
  • Arrays come with dozens of built-in methods for slicing, sorting, and searching.

Try It Yourself

  1. Make an array of your five favorite foods. Print the third one.
  2. Add a sixth food. Print the length of the array.
  3. Make a multidimensional array of your favorite albums by genre.

Part Two · Explorers · Chapter Five

Operators, Expressions, and Choices

How computers do math — and how they decide what to do next.

An expression is a piece of code that produces a value. 1 + 1 is an expression. So is a = 5. The bits of data inside an expression are called operands, and the symbols that connect them are called operators.

JavaScript has many kinds of operators. The arithmetic ones do math: +, -, *, /, and % for remainder. The assignment one, =, gives a value to a variable. The comparison ones check whether things are equal or different: ==, ===, !=, !==, >, <, >=, <=. And the logical ones — &&, ||, ! — combine true-and-false questions together.

console.log(2 + 3);        // → 5
console.log(10 - 4);       // → 6
console.log(6 * 7);        // → 42
console.log(20 / 4);       // → 5
console.log(5 % 2);        // → 1
console.log(3 > 2);        // → true
console.log(3 === 3);      // → true
console.log("3" === 3);    // → false (different types!)

When several operators appear together, JavaScript follows a rulebook called operator precedence to decide which one goes first. Multiplication and division go before addition and subtraction. Parentheses always win. When in doubt, add parentheses — your readers will thank you.

Now for the big trick: making the computer choose. Use if to test a condition, and else to handle the other side.

let isRaining = false;

if (isRaining) {
  console.log("Take an umbrella!");
} else {
  console.log("Take sunglasses!");
}

You can chain choices with else if, and if you have many possible values, the switch statement is a tidy way to list them all. Just remember the break statement after each case — without it, the computer falls straight through to the next one.

let language = "Spanish";

switch (language) {
  case "English":
    console.log("Hello!");
    break;
  case "Spanish":
    console.log("Hola!");
    break;
  case "German":
    console.log("Guten Tag!");
    break;
  default:
    console.log("I don't speak " + language + ".");
}

Key Ideas

  • An expression produces a value; operators combine operands.
  • Arithmetic: + - * / %. Assignment: =. Comparison: == === != !== > < >= <=. Logical: && || !.
  • Operator precedence decides the order. Parentheses override it.
  • if / else lets you choose. else if chains more choices.
  • switch is a tidy way to pick among many values. Use break to stop falling through.

Try It Yourself

  1. Write a program that prints "Good morning" if the hour is before 12.
  2. Use a switch statement to greet in three languages.
  3. What happens if you forget a break in a switch? Try it and see.

Part Two · Explorers · Chapter Six

Round and Round We Go

How to make the computer repeat something without getting bored.

Suppose you want to count from 1 to 100. You could write a hundred lines of code, but that would be silly. Programmers are lazy in a clever way: they find shortcuts. The shortcut for repeating something is called a loop.

The most common loop is the for loop. It bundles three things together: where to start, how long to continue, and how to change after each round.

for (let number = 1; number <= 5; number++) {
  console.log(number);
}
// → 1, 2, 3, 4, 5

There is also the while loop, which keeps going as long as a condition stays true. And the do...while loop, which runs at least once before it checks. And the for...in loop, which walks through every property of an object.

let count = 1;

while (count <= 3) {
  console.log("Round " + count);
  count = count + 1;
}

let i = 0;
do {
  i++;
  console.log(i);
} while (i < 3);

Sometimes you need to stop a loop early. The word break jumps out of the loop immediately. The word continue skips the rest of this round and starts the next one.

for (let i = 0; i <= 10; i++) {
  if (i % 2 !== 0) {
    continue; // skip odd numbers
  }
  console.log(i + " is even");
}

Loops are everywhere. They draw patterns, shuffle cards, count coins, and (as you will see later) run games and animations. Get comfortable with them — they will be your friends for the rest of your programming life.

Key Ideas

  • A loop repeats instructions until a condition stops being true.
  • for bundles a counter, a condition, and an update in one line.
  • while checks the condition before each round; do...while checks after.
  • for...in walks through the properties of an object.
  • break exits the loop; continue skips to the next round.

Try It Yourself

  1. Print the even numbers from 2 to 20.
  2. Print "Hello!" five times using a loop.
  3. What happens if the condition in a while loop never becomes false?

Part Two · Explorers · Chapter Seven

Getting Functional

Write it once. Use it forever.

Imagine a very small machine with a funnel on top and a crank on the side. Drop a number in the funnel, turn the crank, and out comes the square of that number. Drop in 3, out comes 9. Drop in 5, out comes 25. You do not have to know how the machine works inside; you only have to know what it does.

That machine is called a function. A function is a little package of code you write once and call whenever you need it.

function square(x) {
  return x * x;
}

console.log(square(3)); // → 9
console.log(square(5)); // → 25

The word function starts the definition. square is the name. x is the parameter — the slot where you drop something in. The return keyword hands a value back to whoever called the function.

Functions can have many parameters, or none at all. They can take an arguments object that holds every value passed in, even when the number of arguments varies.

function welcomeAll() {
  let message = "Welcome, ";
  for (let i = 0; i < arguments.length; i++) {
    message += arguments[i] + " ";
  }
  return message;
}

console.log(welcomeAll("Ada", "Pip", "Rex"));
// → Welcome, Ada Pip Rex

Functions can also be written without a name — those are called anonymous functions. Sometimes you write an anonymous function that runs immediately, called a self-executing anonymous function. And sometimes a function calls itself, which is called recursion. Recursion is powerful, but be careful: every recursive function needs a stopping condition, or it will loop forever.

function countdown(n) {
  if (n === 0) {
    console.log("Blast off!");
    return;
  }
  console.log(n);
  countdown(n - 1);
}

countdown(3);

One last idea: variables created inside a function are only visible inside that function. This is called function scope. It keeps your program tidy and prevents names from colliding with each other.

Key Ideas

  • A function is a reusable block of code with a name.
  • Parameters are the slots; arguments are the values you give them.
  • return sends a value back to the caller.
  • Anonymous functions have no name; self-executing ones run immediately.
  • Recursion is a function calling itself — always give it a stopping condition.
  • Variables inside a function belong to that function's scope.

Try It Yourself

  1. Write a function called double that returns twice its argument.
  2. Write a function that returns the sum of any number of arguments.
  3. Write a recursive function that counts down from any number to zero.

Part Two · Explorers · Chapter Eight

Making and Using Objects

Grouping related things together — and giving them powers.

An array is great when all its items are the same kind of thing. But what if you want to describe a person — name, age, favorite color, whether they can whistle? An array cannot tell you which item is which. You need a new tool: the object.

An object is a collection of properties, each with a name and a value. It looks like an array, but with names instead of positions:

let ada = {
  name: "Ada",
  age: 12,
  favoriteColor: "teal",
  canWhistle: true
};

console.log(ada.name);          // → Ada
console.log(ada.favoriteColor); // → teal

You can reach into an object with a dot, or with square brackets and a string. The dot is the friendlier style; the brackets are useful when the property name lives in a variable.

ada.age = 13;
console.log(ada.age); // → 13

let key = "favoriteColor";
console.log(ada[key]); // → teal

delete ada.canWhistle;
console.log(ada.canWhistle); // → undefined

Properties can also hold functions. When a function lives inside an object, we call it a method. Inside a method, the word this refers to the object the method belongs to.

let sandwich = {
  meat: "ham",
  cheese: "cheddar",
  bread: "wheat",

  describe: function() {
    return this.bread + " with " + this.meat + " and " + this.cheese;
  }
};

console.log(sandwich.describe());
// → wheat with ham and cheddar

Objects can also be blueprints for other objects. A constructor function is a recipe for making new objects of a certain type. And when one type of object builds on top of another, we call it inheritance.

function Person(name) {
  this.name = name;
  this.eyes = 2;
  this.feet = 2;
}

let willie = new Person("Willie Nelson");
console.log(willie.name); // → Willie Nelson
console.log(willie.feet); // → 2

Objects are how programmers model the world. A game character, a message, a recipe, a shopping cart — each becomes an object with its own properties and methods. Once you see objects, you see them everywhere.

Key Ideas

  • Objects hold named values, called properties.
  • Reach a property with object.key or object["key"].
  • delete removes a property.
  • A method is a function that belongs to an object. this points to the object.
  • Constructor functions build new objects of a type.
  • Inheritance lets one type of object reuse another's properties.

Try It Yourself

  1. Create an object describing yourself — name, age, and a fun fact.
  2. Give your object a method that returns a friendly greeting.
  3. Create a Book constructor, then make two books from it.

Part Two · Explorers · Chapter Nine

Manipulating Documents

How JavaScript brings a web page to life.

Every web page you visit is a little scene made of HTML — the structure, the text, the buttons, the pictures. JavaScript can step onto that scene and rearrange it. It can change text, add images, hide things, show things, respond to clicks.

The browser hands JavaScript a model of the whole page, called the DOM — the Document Object Model. The DOM is a tree. Every element on the page is a little node in that tree. Some nodes are elements (like a <p>), some are attributes, some are text, some are comments. The whole tree starts at a single root: the document node.

let heading = document.querySelector("h1");
heading.textContent = "Hello, new world!";

That little line finds the first heading on the page and changes its text. In one command, the visible page has changed.

There are several ways to find an element. The most famous is getElementById. There are also getElementsByTagName and getElementsByClassName, each of which returns a list of matching elements.

let pageTitle = document.getElementById("page-title");

let allParagraphs = document.getElementsByTagName("p");
for (let i = 0; i < allParagraphs.length; i++) {
  allParagraphs[i].innerHTML = "Paragraph number " + (i + 1);
}

You can change an element's content with innerHTML, set attributes with setAttribute, create brand-new elements with document.createElement, add them to the page with appendChild, and remove them by asking their parent to let them go with removeChild.

let newItem = document.createElement("li");
newItem.innerHTML = "A new list item";
document.getElementById("my-list").appendChild(newItem);

This is what makes web pages feel alive: they can change while you are looking at them. No reloading, no refreshing — just a page that responds.

Key Ideas

  • The DOM is a tree of nodes that represents the page.
  • Nodes have parents, children, and siblings.
  • getElementById, getElementsByTagName, and getElementsByClassName find elements.
  • innerHTML reads or replaces an element's contents.
  • You can create elements with document.createElement and add them with appendChild.
  • You can remove elements by asking the parent to removeChild.

Try It Yourself

  1. Find a paragraph on a page and change its text with innerHTML.
  2. Create a new <li> element and append it to a list.
  3. Select the first heading with getElementById and change its color.

Part Two · Explorers · Chapter Ten

Using Events

How to listen for what the user does.

Every moment in a browser, something is happening. The page loads, a key is pressed, a mouse moves, a button is clicked. These happenings are called events. JavaScript's job is to listen for them and respond.

There are three ways to attach a listener to an event. The simplest is the inline handler, written right on the HTML element:

<button onclick="alert('Hello!');">Click Me</button>

The second is to set an element's event property from JavaScript:

document.getElementById("myButton").onclick = function() {
  alert("Hello!");
};

The third — and most flexible — is addEventListener. It lets you attach many listeners to the same element, and it gives you more control:

let button = document.getElementById("myButton");

button.addEventListener("click", function() {
  console.log("You clicked the button!");
});

When events happen inside other events — a click on a word inside a button, for example — the browser has to decide which listener runs first. It can bubble (inner first, then outer) or capture (outer first, then inner). You choose by passing true or false as the third argument to addEventListener. If you want to stop the event from continuing, call stopPropagation.

element.addEventListener("click", handler, false); // bubbling
element.addEventListener("click", handler, true);  // capturing

function handler(event) {
  event.stopPropagation();
}

Events are what make a page interactive. Without them, your JavaScript would just sit there. With them, your code can respond to the world.

Key Ideas

  • Events are the things that happen in a browser.
  • You can listen with an inline handler, an event property, or addEventListener.
  • addEventListener lets you attach multiple listeners to one element.
  • Events bubble up from inner to outer, or capture from outer to inner.
  • stopPropagation stops an event from continuing.

Try It Yourself

  1. Add a button to a page and log a message when it is clicked.
  2. Attach two different listeners to the same button.
  3. Nest a span inside a div, attach a click to each, and watch which fires first.

Part Two · Explorers · Chapter Eleven

Input and Output

How to ask the user for something — and check their answer.

The primary way to get information from a user is the form. A form holds text fields, drop-down menus, checkboxes, and buttons. In HTML, forms are made with the <form> element, and their fields are made with <input>, <select>, <textarea>, and <button>.

<form name="subscribeForm">
  <label for="firstName">First Name:</label>
  <input type="text" name="firstName" id="firstName">

  <label for="email">Email:</label>
  <input type="email" name="email" id="email">

  <button type="submit">Subscribe!</button>
</form>

JavaScript sees a form through the Form object. You can reach any field by name, read its value, set its value, or call reset() to clear it and submit() to send it.

let firstName = document.forms.subscribeForm.firstName.value;
document.forms.subscribeForm.firstName.value = "Ada";

document.forms.subscribeForm.reset();

Forms are also a great place to validate what the user typed. Does the email look like an email? Is the age a number? Before the form is sent to the server, JavaScript can check these things and warn the user.

function validateEmail(email) {
  let re = /\b[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,4}\b/i;
  return re.test(email);
}

if (!validateEmail(input.value)) {
  alert("Please enter a valid email address.");
}

Good input and output are the difference between a page that shouts at you and a page that talks with you. Take time to design both sides.

Key Ideas

  • Forms gather input: text fields, drop-downs, checkboxes, buttons.
  • The Form object gives JavaScript access to form fields and their values.
  • reset() clears a form; submit() sends it.
  • Always validate user input before doing something with it.
  • A gentle error message is better than a crash.

Try It Yourself

  1. Build a form with one text field and one button.
  2. When the button is clicked, print the value of the field.
  3. Add a validation rule: warn the user if the field is empty.

Part Two · Explorers · Chapter Twelve

CSS and Graphics

When the DOM is not enough — draw, style, animate.

Every element on a page can be styled. The browser keeps track of all its styles in an object called the Style object, and JavaScript can read and change them any time. That is how a page can change appearance while you are looking at it.

let box = document.getElementById("my-box");
box.style.backgroundColor = "tomato";
box.style.width = "200px";
box.style.height = "100px";

To read a style that came from a stylesheet (not just from an inline attribute), use window.getComputedStyle:

let color = window.getComputedStyle(box).getPropertyValue("color");

Once you can change styles, you can animate them. Move a square across the screen by changing its left value inside a loop, but slow the loop down with setTimeout so human eyes can follow it.

function moveSquare(left) {
  document.getElementById("square").style.left = left + "px";
  if (left < 500) {
    setTimeout(function() { moveSquare(left + 1); }, 10);
  }
}
moveSquare(0);

Images are just as easy to control. The Image object lets you change an image's src, width, and height. That is how rollover buttons work: hover over the image, and JavaScript swaps in a different picture. It is also how slideshows work — one image at a time, stepping through an array, with setTimeout to trigger the next one.

function swapImage(img) {
  img.src = "button2.png";
}

function swapBack(img) {
  img.src = "button1.png";
}

CSS3 also has built-in animation properties — animation-name, animation-duration, animation-play-state, and more — that let JavaScript pause and resume an animation that CSS describes. Between the Style object and CSS3 animations, you can make almost anything move, change color, or fade away.

Key Ideas

  • The Style object lets JavaScript read and set an element's inline styles.
  • window.getComputedStyle gives you the stylesheet's actual values.
  • Change styles inside a setTimeout loop to create animation.
  • The Image object lets you change an image's src, size, and more.
  • CSS3 animation properties can be controlled from JavaScript.

Searching with Regular Expressions

Finding shapes inside text.

Sometimes you need to find all the email addresses in a giant wall of text, or all the phone numbers in a document, or all the dates in a list. You could loop over every character by hand, but there is a better tool: the regular expression.

A regular expression is a tiny language for describing patterns. You write the pattern once, and the computer finds every match. Here is one that finds any sequence of digits:

let digits = /\d+/g;

let text = "I have 3 cats and 12 goldfish.";
console.log(text.match(digits)); // → ["3", "12"]

The slashes mark the start and end of the pattern. \d means "any digit." The + means "one or more." The g at the end means "global — find all matches, not just the first."

Regular expressions can describe almost any pattern. The main special characters are worth memorizing. ^ and $ anchor to the start and end. *, +, and ? mean "zero or more," "one or more," and "zero or one." [abc] matches any single character from a set. \d matches a digit, \w matches a word character, \s matches a space. And | means "or."

let email = /\b[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,4}\b/i;

console.log("Contact: ada@example.com or pip@school.org".match(email));
// → ["ada@example.com", "pip@school.org"]

Regular expressions are powerful, but they have a reputation for being cryptic. Start with the common pieces, build slowly, and test often. Use test to ask "does it match?", exec to get details about the match, and match, search, replace, and split to work with strings. And remember: i makes a search case-insensitive; g finds every match; m treats each line as a fresh start.

Key Ideas

  • Regular expressions describe patterns in text.
  • Write them as literals /.../ or with new RegExp("...").
  • Special characters: \d \w \s . * + ? ^ $ [ ] |.
  • Modifiers: g (global), i (ignore case), m (multiline).
  • Use test, exec, match, search, replace, and split to put them to work.

Try It Yourself

  1. Write a regular expression that matches all the words starting with "b" in a sentence.
  2. Find all the numbers in a paragraph that contains dates and prices.
  3. Use replace with a regular expression to turn "cat" into "dog" everywhere.

Callbacks and Closures

When functions can take other functions as gifts.

Here is a wild idea: in JavaScript, functions are values. You can put them in variables, pass them to other functions, and return them from functions. This is not just a curiosity — it is the single most powerful feature of the language.

A function that takes another function as an argument is called a higher-order function. The function you pass in is called a callback. You are telling one machine to use another machine as part of its job.

function doMath(number1, number2, callback) {
  let result = callback(number1, number2);
  document.write("The result is: " + result);
}

doMath(5, 2, function(a, b) { return a * b; });
doMath(10, 3, function(a, b) { return a / b; });

You can use anonymous callbacks, as above, or named ones. Named callbacks are often easier to read and easier to reuse.

function multiply(a, b) { return a * b; }

doMath(5, 2, multiply);

Now for a subtler idea: the closure. A closure is a function that remembers the variables from where it was created — even after that outer function has finished running.

function makeGreeting(phrase) {
  let message = phrase + ", welcome!";
  return function() {
    console.log(message);
  };
}

let sayHello = makeGreeting("Hello");
sayHello(); // → Hello, welcome!

let sayHi = makeGreeting("Hi");
sayHi();    // → Hi, welcome!

Each call to makeGreeting creates a fresh message, and each returned function remembers its own. This is called a function factory — a function whose job is to build other functions. And it is exactly the trick that powers custom error messages, cached calculations, and many of the effects you see on modern websites.

Callbacks and closures are two of the most powerful ideas in JavaScript. They take a little while to feel natural. Be patient with yourself. Once they click, the whole language opens up.

Key Ideas

  • Functions are values. You can pass them around like anything else.
  • A callback is a function passed to another function.
  • Named callbacks can be easier to read and reuse than anonymous ones.
  • A closure remembers the variables from where it was created.
  • A function factory is a function whose job is to build other functions.

Try It Yourself

  1. Write a function called runTwice that takes a callback and calls it twice.
  2. Write a function factory that builds a "greeter" for any name you give it.
  3. What is the difference between a callback and a closure?

AJAX and JSON

How your programs talk to the wider world.

Every time you visit a website, two computers have a conversation. Your computer asks for something, and another computer — far away — answers. The rules of that conversation are called HTTP, and learning them is the key to building web apps that talk to servers.

But there is a trick: a web page can send a request in the background, without reloading the whole page. That trick is called AJAX, and it is what makes Gmail and Google Maps and countless other sites feel smooth.

let request = new XMLHttpRequest();
request.open("GET", "data.txt", true);
request.onload = function() {
  document.getElementById("content").innerHTML = request.responseText;
};
request.send();

That is the whole heart of AJAX: create a request, set a callback, open it, send it. When the answer arrives, your callback runs and updates the page.

Most modern sites send their data as JSON — JavaScript Object Notation. It looks almost exactly like a JavaScript object literal, which makes it very easy to work with.

let data = JSON.parse(request.responseText);
document.getElementById("title").innerHTML = data.book_title;
document.getElementById("author").innerHTML = data.book_author;

For security, browsers guard their users carefully. A page can only fetch data from its own domain, unless the server on the other side explicitly says "yes, this is allowed" using a header called CORS. That rule is what keeps the web safe. Respect it. Understand it. Use it.

AJAX + JSON is the engine of the modern web. Every app you love — every feed that updates, every search that autocompletes, every chat that scrolls — is powered by this same simple idea: ask, wait, receive, update.

Key Ideas

  • AJAX lets a page fetch data without reloading.
  • XMLHttpRequest sends the request and handles the response.
  • JSON is the standard text format for structured data.
  • JSON.parse turns a JSON string into a JavaScript object.
  • The same-origin policy and CORS keep AJAX safe.

Try It Yourself

  1. Use XMLHttpRequest to load a text file and print its contents.
  2. Fetch a JSON file and print one of its fields.
  3. What does a 404 status code mean? What about a 500?

Part Three · Masters · Chapter Sixteen

Controlling the Browser

The Window object, the Navigator, and the hidden gears of the browser.

Behind every web page is a whole machine: a browser. It has a user interface, a loader that downloads files, parsers that read HTML and CSS and JavaScript, a layout engine, and a renderer. All of that machinery is exposed to JavaScript through an API called the Browser Object Model, or BOM.

The main object you will use is the Window object. Each browser tab is one Window. Through it you can open a new page, go back in history, measure the window, or pop up an alert.

window.location = "https://example.com";
window.history.back();
console.log(window.innerWidth + " x " + window.innerHeight);

window.alert("Hello!");
window.prompt("What is your name?");

One small but powerful object is the Navigator, which tells you about the browser itself: its name, its version, whether it is online, what language it uses. Some of its values are surprisingly old-fashioned — navigator.appName, for example, still says "Netscape" in most browsers, a leftover from the early days.

console.log(navigator.userAgent);
console.log(navigator.language);
console.log(navigator.onLine);

The Window object also gives you timers: setTimeout runs a function once, after a delay, and setInterval runs it again and again, forever. Together with clearTimeout and clearInterval, they let you build clocks, sliders, and animations.

let timer = setInterval(function() {
  console.log("tick");
}, 1000);

// later
clearInterval(timer);

The BOM is what makes a web page feel like an application. It is how you turn a document into a window onto the world.

Key Ideas

  • The Browser Object Model is JavaScript's handle on the browser itself.
  • Each tab is a Window object. Through it you control location, history, size, and popups.
  • The Navigator object tells you about the browser: name, version, language, online status.
  • setTimeout runs a function once; setInterval runs it repeatedly.
  • The BOM turns a document into an application.

Try It Yourself

  1. Use window.location to load another page.

  3. Make a timer that logs "tick" every second.

Part Three · Masters · Chapter Seventeen

HTML5 APIs and Media

When JavaScript reaches out of the browser and touches the world.

An API — Application Programming Interface — is a set of rules that tells one program how to talk to another. When you ask your browser for your location, or your camera feed, or your battery level, you are using an API.

HTML5 introduced a whole family of APIs to the web. There are APIs for geolocation (where are you?), file access (which file did you pick?), drag and drop (what did you drag?), web storage (remember this for me), web sockets (let's keep a conversation open), and getUserMedia (let me see your camera).

The Geolocation API is a lovely example. It asks the browser, which asks the operating system, which asks the hardware. If the user gives permission, you get back an object with latitude, longitude, altitude, heading, speed, and accuracy.

navigator.geolocation.getCurrentPosition(function(position) {
  console.log("Latitude: " + position.coords.latitude);
  console.log("Longitude: " + position.coords.longitude);
});

Another favourite is getUserMedia. It gives a page access to the camera and microphone — that is how video chat works without a plugin.

navigator.getUserMedia(
  { video: true, audio: false },
  function(stream) {
    let video = document.getElementById("camera");
    video.src = URL.createObjectURL(stream);
    video.play();
  },
  function(error) {
    alert("Something went wrong: " + error.code);
  }
);

Not every browser supports every API at the same moment. Always check before you use one. A common technique is feature detection: if the feature exists, use it; if not, fall back gracefully. And there are tools called polyfills that fill in the gaps for older browsers.

HTML5 APIs give the web superpowers. Geolocation, camera, audio, storage, sockets — these used to need plugins. Now they are part of the platform. And you can use them from plain old JavaScript, in any modern browser.

Key Ideas

  • An API is a set of rules that lets one program talk to another.
  • HTML5 provides APIs for geolocation, files, media, storage, and more.
  • navigator.geolocation gives you the device's position.
  • navigator.getUserMedia gives you the camera and microphone.
  • Always do feature detection, and use polyfills for old browsers.

Try It Yourself

  1. Ask the browser for your location and print the latitude and longitude.

  3. Write a feature check for navigator.geolocation. What happens if it is missing?

Part Three · Masters · Chapter Eighteen

Write Less, Do More with jQuery

The friendly shortcut that changed the web.

By now you have written a lot of plain JavaScript. You have selected elements with document.getElementById, attached listeners with addEventListener, and animated styles by hand. It works. But it is a lot of typing — and every browser used to do things a little differently.

Enter jQuery — a small library that smooths out the rough edges. It makes selecting, styling, animating, and fetching data much shorter. It works everywhere. And it is used by more than half the top websites in the world.

You include it with a single <script> tag from a CDN. Then you use the $ function — short for jQuery — to select elements and chain methods onto them.

$("#pageHeader")
  .text("Hello, world!")
  .css("color", "red")
  .css("font-size", "60px");

Every jQuery selection waits for the page to be ready with $(document).ready(). Inside, you can select elements just like CSS selectors: $("p"), $(".myclass"), $("#myid"). You can attach events with .on(), remove them with .off(), and swap them for one-line shortcuts like .click() or .hover().

$("#colorizer").on("click", function() {
  $("tr:even").css("background", "yellow");
});

jQuery's effects are famous. .hide(), .show(), .toggle(), .fadeIn(), .fadeOut(), .slideUp(), .slideDown(), and .animate() give you polished animations with a single line. Pass in a duration, an easing function, and a callback, and you have a full-fledged effect.

$("#box").animate({
  width: "800px",
  color: "blue"
}, 5000);

And jQuery's AJAX helpers — $.ajax(), $.get(), $.post(), $.getJSON() — make fetching data almost trivially short. The days of writing out XMLHttpRequest by hand are over.

jQuery is not the only library — and it is not the newest. But it is the one that made the modern web possible, and it is still a wonderful thing to learn. Write less, do more.

Key Ideas

  • jQuery is a small library that makes JavaScript shorter and cross-browser.
  • Include it with a <script> tag from a CDN.
  • Use $ or jQuery to select elements, then chain methods.
  • $(document).ready() waits for the page before running.
  • Effects: hide, show, fadeIn, slideDown, animate.
  • AJAX helpers: $.ajax, $.get, $.post, $.getJSON.

Try It Yourself

  1. Include jQuery on a page and change a heading's color with .css().
  2. Make a button that fades a div in and out with .fadeToggle().
  3. Use $.get() to load a text file into a div.

Part Three · Masters · Chapter Nineteen

Bugs, Tools, and What Comes Next

The last few skills you need to become a proper JavaScript programmer.

Nobody writes perfect code. Every programmer, every day, writes mistakes. These mistakes are called bugs, and finding them is called debugging. The good news is that most bugs are the same dozen mistakes, and once you know them, you can spot them from across the room.

Here are the classics. Equality confusion — using = when you meant == or ===. Mismatched brackets — opening one and forgetting to close it. Mismatched quotes — starting with " and ending with '. Missing parentheses around a compound condition. Missing semicolons at the end of statements. Capitalization errors — getElementByID is wrong, it is getElementById. Bad variable names — using a reserved word by accident. Scope errors — creating a global when you meant a local. Wrong number of arguments in a function call. And counting errors — forgetting that JavaScript arrays start at 0.

// BUG: = instead of ===
if (a = 5) { /* ... */ }

// BUG: missing closing bracket
let obj = { name: "Ada" ;

// BUG: mismatched quotes
let s = "hello';

There is a whole ecosystem of tools to help you find these bugs before they find you. JSLint and JSHint check your code for problems. JSFiddle and JSBin let you try snippets in a sandbox. JSBeautifier makes messy code readable. JavaScript Compressor makes clean code small. The Mozilla Developer Network is the best JavaScript reference on the planet. And Douglas Crockford's website has free videos that will take you from beginner to expert.

Beyond the basics, there is an enormous universe of frameworks and libraries. Angular, Backbone, Ember, React, Vue, Svelte, Knockout, Famo.us, Handlebars, Underscore, Modernizr, QUnit — each solves a different problem. Learn one or two well. The rest will feel familiar.

You have finished the book — but you have not finished learning. Programming is a craft, and crafts are built through practice. Keep writing code. Keep breaking it. Keep fixing it. The more you build, the more fluent you become.

Key Ideas

  • Most bugs come from a dozen common mistakes. Learn to spot them.
  • Use === not ==. Match your brackets. Match your quotes. Use semicolons.
  • Remember: JavaScript arrays start at 0.
  • Online tools like JSLint, JSFiddle, and MDN will make you a better programmer.
  • Frameworks like Angular, React, Vue, and Ember are waiting when you are ready.

Try It Yourself

  1. Copy a piece of code from this book into JSLint. What does it say?
  2. Write a program with a deliberate bug and find it by reading the error message.
  3. Pick one framework from the list above and read its first tutorial.
